# Docker image tracking model and registry client

Track container images via Jib Core (`com.google.cloud.tools:jib-core`) in a dedicated `docker_images` table (`image_name`, `manifest_digest`, `template_name`, and an optional unique foreign key `repo_name` referencing `releases(repo)` with `ON UPDATE CASCADE ON DELETE CASCADE`), alongside a `registry_credentials` table supporting authentication across multiple container registries simultaneously. Any user-supplied tag or digest is stripped on input so every tracked image monitors the top-level manifest digest of `:latest`. Each tracked Docker image uses its own `template_name`, except when a linked Docker image and its parent GitHub repository both change in the same check cycle—in which case both stored states are updated and only the GitHub release ticket is created.
